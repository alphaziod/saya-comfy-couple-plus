# Internationalisation

## Model

- 14 locales in `src/locales/<code>.json`: `fr` (source), `en`, `es`, `pt-BR`, `tr`, `id`, `vi`,
  `zh-CN`, `zh-TW`, `ja`, `ko`, `th`, `ru`, `ar`.
- **Keys are the French source text.** `fr.json` maps each key to itself; other locales map it to
  their translation. Lookup order: current locale → `en` → the key itself.
- Loaded once through static Vite imports (`src/lib/i18n.ts`); pure helpers live in
  `src/lib/i18n-core.ts` so Node tests can import them.
- Arabic switches `<html dir="rtl">`; CSS uses logical properties (`margin-inline-start`, ...).

## API (Svelte)

```svelte
{$t('Galerie')}
{$t('{n} LoRA envoyée(s) vers {slot}', { n, slot })}
{$tn('{n} image', '{n} images', count)}
```

- `{name}` placeholders are substituted after lookup; `{n}` is always the count in `$tn`.
- Plurals follow CLDR (`Intl.PluralRules`). Most locales need only the two plain keys.
  Russian and Arabic add suffixed keys `"<plural key>|few"`, `"|many"` (Arabic also `|zero`, `|two`).
- Text produced outside components (core error messages, library code) goes through
  `src/lib/translate-now.ts`, which translates with the current locale at call time.

## Adding or changing a string

1. Write the French text in the component with `$t(...)`.
2. Add the key to all 14 locales. For many keys, write `src/locales-staging/<topic>.json`
   (`{ "<key>": { "fr": "...", "en": "...", ... } }`), run
   `python3 -I scripts/merge-locale-staging.py "$PWD"`, then delete `src/locales-staging/`.
3. Run `node --test scripts/i18n.test.mjs`. It fails on: a key used in code but missing in a
   locale, placeholders that differ from the French key, unused keys, missing `ru`/`ar`
   plural forms, orphan plural forms.

Changing French text changes the key: update every locale (the test lists what is missing) and
remove the old key. Native smokes match a few French labels; check `scripts/*-native-smoke.js`.

## What is not translated

Identifiers, logs, comments and developer docs are English. Persisted values (preference keys,
IPC action names, SQL) never depend on the UI language.
